# AI recipe suggestions: setup guide

Everything for AI suggestions is already built and tested. **Adding one API key switches it on.**
Until then the Ideas button explains that AI is not set up, and nothing else is affected.

You can try the whole flow right now without a key, see [Try it without a key](#try-it-without-a-key).

## What you get

On the Home or Recipes screen, tap **Ideas** (or **Suggest recipes**). Pick a theme, optionally
add a note ("something light, I am tired") and a number of ideas. The server sends your pantry to
the AI model and returns recipes that mostly use what you have, with anything missing marked
"need to buy" and one tap to add it to your shopping list.

## Step 1. Get a Gemini API key

1. Go to https://aistudio.google.com/apikey and sign in with a Google account.
2. Click **Create API key** (choose a new or existing Google Cloud project when asked).
3. Copy the key. It starts with `AIza`.

Google offers a free tier with rate limits, and a paid tier that needs billing. Prices, limits and
the data-use terms change, so read the current terms on that page. In particular check whether
prompts sent on the free tier may be used by Google to improve its products, if that matters to you.

**What is sent to Google with each request:** the names of the ingredients in your pantry, your diet
type, your allergy list, the theme and your note. Not your name, email, expenses or tasks.

## Step 2. Give the key to the server

The key lives **only on the server**, never in the app and never in git.

**macOS / Linux / Git Bash**

```bash
export GEMINI_API_KEY="AIza...your key..."
mvn spring-boot:run
```

**Windows PowerShell**

```powershell
$env:GEMINI_API_KEY = 'AIza...your key...'
mvn spring-boot:run
```

With Docker Compose or a hosting service, set `GEMINI_API_KEY` in the `.env` file or in the
service's environment settings (see `.env.example`).

On startup the log must say:

```
AI suggestions are on, using Gemini model gemini-2.5-flash
```

If it says `AI suggestions are off: no GEMINI_API_KEY set`, the variable is not set in that terminal.

## Step 3. Try it

Open the app, go to **Recipes, Ideas**, and tap **Suggest recipes**. Make sure your pantry has a few
ingredients first.

## Settings

All optional. Set them as environment variables next to `GEMINI_API_KEY`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `GEMINI_MODEL` | `gemini-2.5-flash` | Which Gemini model to use. See the note below if the name is rejected. |
| `AI_DAILY_LIMIT` | `20` | Suggestions each user may request per day. Over it, the API answers 429. |
| `AI_CACHE_MINUTES` | `30` | Asking again with the same pantry, theme and note reuses the saved recipes for this long, at no cost. `0` turns it off. |
| `AI_PROVIDER` | `auto` | `auto` uses Gemini when a key is set. `demo` returns made-up recipes. `none` switches suggestions off. |

**About the model name.** `gemini-2.5-flash` was the current Flash model when this was written. Google
renames and retires models over time. If the app says *"The AI model was not found. Check
GEMINI_MODEL"*, open https://aistudio.google.com and use the name of the Flash model it lists, then set
`GEMINI_MODEL` to it.

## Try it without a key

```bash
export AI_PROVIDER=demo        # PowerShell: $env:AI_PROVIDER = 'demo'
mvn spring-boot:run
```

Recipes are then generated by a small built-in stand-in, clearly labelled "(demo)", and the app shows a
"Demo mode" notice. Everything else is real: validation, allergy and diet filtering, pantry matching,
saving, the daily limit and the screens. One demo recipe always contains peanuts, so if you list
peanuts as an allergy you can watch it being removed.

## How it keeps results safe and cheap

| Concern | What happens |
| --- | --- |
| **Allergies** | Checked **in code**, never trusted to the model. Any recipe whose title, ingredients or steps mention an allergen is dropped. General names also cover common members: *shellfish* covers prawn, crab and so on; *dairy* covers milk, paneer, ghee, curd and so on; *nuts*, *gluten*, *fish*, *soy*, *egg* and *sesame* work the same way. The check errs on the side of dropping too much (for example "nut" also catches "coconut"). |
| **Diet** | A recipe whose declared type does not fit your diet (or cannot be read) is dropped. |
| **Missing ingredients** | Worked out by comparing each ingredient with your real pantry, not by the model's claim. Staples such as salt, water, oil, pepper and sugar count as always available. |
| **Bad model output** | The answer must be valid JSON in a fixed shape, with sensible ranges. If not, the server asks once more with a repair instruction. If that also fails you get a clear error, and the attempt is recorded. |
| **Prompt injection** | Your ingredient names and note are cut down to plain letters, numbers and a few punctuation marks, limited in length, and sent as data. The fixed rules tell the model to ignore instructions inside them. This reduces the risk; it cannot remove it completely. |
| **Cost** | Daily limit per user, a short cache for repeats, and the token count of every call is stored. |

See what it has cost with this query on the database:

```sql
SELECT DATE(created_at) AS day, status, COUNT(*) AS requests, SUM(tokens_used) AS tokens
FROM recipe_requests GROUP BY day, status ORDER BY day DESC;
```

Safety filtering is a help, not a guarantee. If an allergy is serious, check every recipe yourself.

## Troubleshooting

| What you see | Meaning and fix |
| --- | --- |
| *AI suggestions are not set up yet* (503) | No key on the server, or `AI_PROVIDER=none`. Do Step 2. |
| *Add some ingredients to your pantry first* (400) | Staples alone do not count. Add real ingredients. |
| *You have used all N AI suggestions for today* (429) | The daily limit. Raise `AI_DAILY_LIMIT`, or wait until tomorrow. Failed attempts count too. |
| *The AI service refused the API key* | Wrong or revoked key, or the Generative Language API is disabled for that Google project. Create a new key. |
| *The AI service rejected the request* | Often an invalid key or an unknown model. Check `GEMINI_API_KEY` and `GEMINI_MODEL`. |
| *The AI model was not found* | Wrong `GEMINI_MODEL`. See the note above. |
| *The AI service quota or rate limit was reached* | Google's limit, not yours. Wait a minute, or use a paid plan. |
| *The AI service declined this request* | Google's safety filter blocked the prompt. Remove the note and retry. |
| *The AI gave an answer that could not be used* | Both attempts returned broken output. Try again. |
| *N suggestions were removed because they clashed* | The allergy or diet filter did its job. Ask again for different ideas, or check your allergy list for over-broad entries. |
| Suggestions feel repeated | You are inside the cache window. Tap **Get fresh ideas**. |

## Using a different AI provider later

The app talks to the model through one small interface, `LlmClient`
(`backend/src/main/java/com/siva/assistant/ai/`). To use OpenAI, Claude or another model, write one more
class that implements it (send the prompt, return the reply text and token count) and select it in
`AiConfig`. The prompt, validation, safety checks, limits and screens do not change.

## What has and has not been tested

- Tested with about 70 automated checks: the exact request sent to Gemini and how its replies and errors are
  read (using realistic responses), prompt building and sanitising, JSON validation, the repair retry,
  allergy and diet filtering, pantry matching (including Hindi ingredient names), the daily limit, the
  cache, and the screens in demo mode.
- **Not tested against the real Gemini service**, because no key was available. The request follows
  Google's documented format, but the first real call is the real test. If something is off, the
  error message in the app and the server log will say what.
